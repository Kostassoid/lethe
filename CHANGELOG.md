# Change Log

## [v1.0.1] - 2026-11-11

### Added

* Partial verification coverage via `--coverage`, sampling the beginning and end of the wiped area.
* Reporting of skipped bad blocks as they are encountered during wiping and verification.
* Unit and integration tests for partial verification, bad-block handling, retries, and non-sequential sanitization
  stream access.
* QEMU/Vagrant VM integration test suite with dedicated scratch disks.
* macOS VM integration testing on Apple Silicon via Tart and `vagrant-tart`.
* Windows ARM64 and Linux ARM64 builds.
* Bash and PowerShell installers generated by cargo-dist.
* Multi-platform CI and release workflows.
* Release automation via `just release <version>`. It runs in dry-run mode by default; pass `--execute` to bump the
  version, update the changelog and README, commit, tag and push the release.
* Publishing to crates.io on release tags.

### Changed

* Reworked the wipe engine around plans, sessions, and seekable sanitization streams. Random data can now be
  regenerated at any byte offset, which makes verification and resume after retries, bad-block skips, and partial
  coverage correct.
* Verification retries now rewrite only the remaining area and resume verification from the failure point.
* Large internal refactor: split the monolithic action and sanitization modules into plan, verification, bad-block,
  scheme, stream, and platform-specific storage modules, and simplified the storage abstractions.
* Migrated the CLI to clap 4 and tightened argument validation, including byte/block-size parsing and type-safe
  percentages.
* Reworked progress and event reporting; progress is now relative to the wiped range when a starting offset is used.
* [Windows] Migrated storage I/O from `winapi` to the official `windows` crate and split enumeration, physical-drive,
  and volume metadata into dedicated modules.
* [Windows] Device listing no longer requires administrator privileges and now reports size, type, labels, and mount
  points for regular users.
* [Windows] Fixed `list` table column alignment.
* Updated dependencies and moved to Rust 2024 edition with Rust 1.99.
* Dropped macOS Intel support.
* Release notes are now generated from this changelog by cargo-dist.
* Added Justfile automation, rustfmt/clippy configuration, and updated CI/release workflows (replacing Travis CI).

### Fixed

* Fixed verification of random data after non-sequential access, bad-block skips, retries, and partial coverage.
* Fixed partial-coverage verification boundaries and coverage handling.
* Fixed progress event ordering and step reporting.
* Fixed Windows device metadata access without elevation by using query-only device handles.
* Fixed progress-bar position and current byte counter when using a starting offset.
* Fixed Linux and macOS device enumeration compilation.
* Fixed known issues in external dependencies.

## [v0.6.0] - 2021-08-15

### Added

* All mounting points associated with a device get unmounted before wiping, including nested partitions/volumes.
  Previously, this caused issues on Windows, for example, when it was impossible to access a physical drive for writing
  if it had any mounted volumes.
* Volume label is now part of the storage device description.

### Changed

* Storage devices are now presented as a tree instead of a flat list. This allows to quickly understand the dependency
  between storage devices.
* Elevated privileges are not required for listing the devices.
* [macOS] Device enumeration implementation was replaced with the one based on 'diskutil'. There upside is that 'sudo'
  is not required for the 'list' command and that the data is more complete. The downside is that this method is pretty
  slow and there is a bug in 'diskutil' tool not returning a correct storage size for APFS volumes.
* [linux] Device enumeration implementation was replaced with the one based on 'sysfs' abstractions. Mostly to get the
  accurate device hierarchy info.
* The progress bar is red now, because DANGER.

## [v0.2.0] - 2019-09-16

This release is mostly laying the groundwork for a more serious improvements.

### Added

* It is now possible to provide block size with a scale unit. E.g. `128k` (128 kilobytes) instead of `131072`.
  Additionally, the number is checked to be a power of two.

### Changed

* Unsuccessful validation now retries at the last successful position.
